# TacPhone Remote Server

A single ASP.NET Core (`net10.0`) process that makes the TacPhone web UI reachable
from any phone on the internet. It does two things:

1. serves the static phone UI from `wwwroot/`,
2. relays WebSocket traffic between one in-game Arma client and the browsers that
   attach to it.

That is the whole scope. Everything else (TLS, DNS, process supervision) is your
host's job.

---

## What it is, what it is not

**It is:**

- a **relay**: exactly one outbound `wss://` connection from the game, plus any
  number of browser sockets; application frames are forwarded 1:1,
- a **static host** for the phone UI (one `index.html`),
- a **bookkeeper** for host identities, device tokens, one-time pair codes and
  share links, stored in a local SQLite file.

**It is not:**

- a TLS endpoint. The app speaks **plain HTTP only**; nginx terminates TLS and
  proxies to the app over loopback.
- an account system. There are no users, passwords or logins — only host
  identities and bearer tokens.
- a message store. Frames are relayed in memory; nothing is queued, replayed or
  archived.
- a cluster. **Single instance, single process.** All live state (connected hosts,
  peers, pending codes) lives in memory, so a second process or a load-balanced
  pair would silently break pairing and routing.

---

## How it works

```
Arma (+ extension) ---- one outbound WSS ----> nginx --TLS--> app :5080
Browser  ------------ one WSS per tab ------> nginx --TLS--> app :5080
```

- The game opens **one** outbound WebSocket, authenticated with a host id and a
  host secret. On first arm the server mints a new identity and returns the
  secret; the game stores it in `profileNamespace`.
- A browser attaches to that host in one of three ways:
  - a **one-time code** (`#p=XXXX-XXXX-XX`, 120 s TTL, single use),
  - a **share link** (`#s=<key>`, reusable until expiry or revoke),
  - a **stored device token** (returned once on first pairing, kept by the
    browser; owner tokens are permanent, share tokens die with the share).
- The server stores `hosts`, `devices`, `pair_codes` and `shares` in SQLite.
- Application frames are **binary** WebSocket messages relayed 1:1. The server
  does not interpret the application JSON; the one exception is terrain requests
  and their replies, which are inspected for the [terrain cache](#terrain-cache).
- Peer ids (`p_…`) are generated by the server, never by a client.

Details of the flow, the state machine and the security model are in
[`../tacphone-remote-relay.md`](../tacphone-remote-relay.md).

## Requirements

| Component | Requirement |
| --- | --- |
| Runtime | .NET 10 **ASP.NET Core** runtime, package `aspnetcore-runtime-10.0`. When the runtime is installed separately from the shared framework, `dotnet-runtime-10.0` is needed too. To *build* the project, install the .NET 10 **SDK**. |
| OS | Linux with systemd (recommended), or Windows (service via `sc.exe`, NSSM or Task Scheduler). |
| Reverse proxy | nginx on the public host. The app itself listens on loopback. |
| DNS | A name pointing at the host, e.g. `tacphone.arma3.io`. |
| TLS | A certificate for that name. Let's Encrypt via certbot is fine. |

The in-game browser and the phone UI need nothing extra: they talk `https://` and
`wss://` to your host name.

## Configuration

Configuration is read from, in increasing precedence:

1. `appsettings.json` next to `TacPhone.RemoteServer.dll`,
2. optional `appsettings.Production.json` in the same directory (loaded because
   the service sets `ASPNETCORE_ENVIRONMENT=Production`),
3. environment variables — either exported by the supervisor or set in
   `/etc/tacphone-remote.env` via `EnvironmentFile=-/etc/tacphone-remote.env`.

Environment variables use `__` (double underscore) for nested keys:
`TacPhone__Port=5080`, `TacPhone__Limits__MaxHosts=2000`. Array elements are
indexed: `TacPhone__TrustedProxies__0=10.0.0.5`.

For local runs and simple deployments, an optional `.env` file is loaded
automatically from the content root, the current directory, or the solution
root (`RemoteServer/`, for `dotnet run --project src/TacPhone.RemoteServer`).
It uses the same syntax (`TacPhone__Port=5080`, `#` comments, optional quotes)
and sits **between** `appsettings.json` and real environment variables: a real
`TacPhone__Port` still wins. This is separate from systemd's
`EnvironmentFile=`, which systemd turns into real environment variables before
the process starts.

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `TacPhone:BindAddress` | string | `127.0.0.1` | Interface the app binds to. Keep it on loopback; see [Port / bind](#port--bind-443-vs-5080). |
| `TacPhone:Port` | int | `443` | TCP port. `443` only when the app itself is the public boundary; nginx setups use `5080`. |
| `TacPhone:DatabasePath` | string | `data/tacphone-remote.db` | SQLite file, relative to the content root (the working directory). The parent directory is created automatically. Must be writable by the service user. |
| `TacPhone:CompressedStaticPath` | string | `""` (empty) | Cache directory for the precompressed `index.html` variants (`index.html.br`, `index.html.gz`, `index.html.sha256`). Empty = `compressed-static` next to the SQLite database (`/var/lib/tacphone-remote/compressed-static` in the recommended layout). A configured value is relative to the content root unless absolute. Must not be `wwwroot` — `/opt` is read-only in production. See [Static compression](#static-compression). |
| `TacPhone:PublicBaseUrl` | string | `""` (empty) | Base URL used to build share links. When empty, the URL is derived from the `Host` header and `X-Forwarded-Proto` of the game connection, which is usually correct behind nginx. Set it explicitly (e.g. `https://tacphone.arma3.io`) if you terminate TLS elsewhere or proxy under a different name. |
| `TacPhone:LogFile` | string | `logs/tacphone-remote.log` | Rolling log file, relative to the content root unless absolute. Leave empty to disable file logging (console/journald only). |
| `TacPhone:LogFileMinLevel` | string | `Information` | Minimum level written to the log file (`Trace`/`Debug`/`Information`/`Warning`/`Error`/`Critical`/`None`). |
| `TacPhone:LogFileMaxBytes` | long | `10485760` (10 MiB) | Rotate the log file when the next line would exceed this size. `0` disables rotation. |
| `TacPhone:LogFileKeep` | int | `5` | Number of rotated files kept (`relay.log.1` … `relay.log.N`). |
| `TacPhone:TrustedProxies` | string[] | `["127.0.0.1", "::1"]` | IPs or CIDR ranges that may set `ForwardedHeaders` (`X-Forwarded-For`, `X-Forwarded-Proto`). Used so rate limiting and logs see the real client IP. Leave loopback when nginx runs on the same host. |
| `TacPhone:Limits:MaxFrameBytes` | int | `33554432` (32 MiB) | Largest accepted application frame. Bigger frames close that peer with a protocol error. |
| `TacPhone:Limits:MaxClientsPerHost` | int | `64` | Concurrent browser sockets per host. |
| `TacPhone:Limits:MaxHosts` | int | `5000` | Concurrent game sockets. |
| `TacPhone:Limits:PairCodeTtlSeconds` | int | `120` | Lifetime of a one-time pair code. |
| `TacPhone:Limits:MaxShareTtlSeconds` | int | `86400` | Upper clamp for a share link TTL (the UI offers 15 min to 24 h). |
| `TacPhone:Limits:AttachAttemptsPerMinutePerIp` | int | `10` | Attach attempts allowed per client IP per minute. |
| `TacPhone:Limits:AttachAttemptsPerMinutePerShare` | int | `60` | Attach attempts allowed per share key per minute. |
| `TacPhone:Limits:IdleTimeoutSeconds` | int | `120` | A socket that sends nothing and answers no keepalive is closed after this long. |
| `TacPhone:TerrainCache:Enabled` | bool | `true` | Cache the game's `RequestTerrainSVG` reply in relay memory. `false` forwards every terrain request as before. |
| `TacPhone:TerrainCache:MaxTotalBytes` | long | `268435456` (256 MiB) | Cap on the **unique** pooled payload bytes. A new payload that would exceed it is forwarded but neither cached nor pinned. `0` keeps nothing new; identical content is always shared. |
| `TacPhone:TerrainCache:PendingTimeoutSeconds` | int | `60` | How long a forwarded terrain request may wait for the game's reply before it is forgotten. |

## Logs

All application logs are written to `TacPhone:LogFile` (default
`logs/tacphone-remote.log`, relative to the content root) **as well as** to the
console/journald. The file is flushed per line, rotates at 10 MiB, and keeps 5
rotated files. Set the path to an absolute location on a systemd host, because
the default is read-only under `ProtectSystem=strict`:

```
TacPhone__LogFile=/var/lib/tacphone-remote/logs/tacphone-remote.log
```

`TacPhone:LogFile` empty disables file logging. Fatal startup failures (for
example a port already in use) are written as `[Critical]` before the process
exits. If the file cannot be opened, the relay logs one warning to stderr and
keeps running with console/journald logging only.

## Port / bind: 443 vs 5080

The app calls `UseUrls($"http://{BindAddress}:{Port}")` — it always speaks plain
HTTP, the scheme is not configurable.

- **Normal setup:** nginx listens on `443` (and `80` for the redirect) and proxies
  to `127.0.0.1:5080`. Set `TacPhone__Port=5080` and leave
  `TacPhone__BindAddress=127.0.0.1`. The app port is never published to the
  network.
- **Binding 443 directly:** possible, but it needs `CAP_NET_BIND_SERVICE` (the
  systemd unit already grants it) and it means **plaintext HTTP on a public
  port**. Only do this when something on the same host terminates TLS and
  forwards into the app, and make sure the port is firewalled off from the
  internet.

Never expose the app port directly to the internet — there is no TLS in the app
and no authentication on `/health` or the static page.

## Endpoints

| Method | Path | Behaviour |
| --- | --- | --- |
| `GET`/`HEAD` | `/`, `/index.html` | Serves `wwwroot/index.html` with `Cache-Control: no-store`, Brotli or gzip compressed when the client accepts it (see [Static compression](#static-compression)). |
| `GET` | `/health` | Anonymous JSON health snapshot (see below). No DB writes. |
| `GET` | `/ws` | WebSocket endpoint. The first control frame selects the role: `auth` with `"role":"game"`, or `attach` with `"role":"client"`. |
| any | anything else | Falls back to the static entry (`index.html`); the UI is hash-routed, so there are no server-side routes. |

`/health` returns, on success:

```json
{
  "status": "ok",
  "version": "0.1.0",
  "uptimeSeconds": 86412,
  "hostsOnline": 3,
  "clientsOnline": 7,
  "terrainCacheEntries": 2,
  "terrainCacheBytes": 18734210,
  "terrainCacheHosts": 3,
  "terrainCacheHits": 41,
  "terrainCacheMisses": 5
}
```

`hostsOnline` counts connected game sockets, `clientsOnline` counts connected
browser sockets. The `terrainCache*` fields are described in
[Terrain cache](#terrain-cache).

## Terrain cache

The Map app asks the game for the terrain SVG with
`{a:"main", c:"RequestTerrainSVG", config}`. Only the in-game browser can render
it, so without a cache every phone that opens the map costs a full game
round-trip (seconds) even though the result only changes once per mission.

The relay keeps the game's reply — the **gzip+base64 string** the in-game browser
produces — in memory. The request config is **not** a cache key: the same config
can produce different terrain in different missions, so it cannot identify a
terrain globally.

- **One pinned result per game host session.** The first terrain reply the game
  returns for a host is pinned to that host until it disconnects; every browser
  attached to that host shares it. A **hit** is answered immediately with
  `{k, d: <pinned>}` and never reaches the game.
- **Config is only compared.** The pin also stores the hash of the config that
  produced it. A request whose config hash matches the pin is a hit; any other
  request is a **miss**, forwarded to the game, and its reply replaces the pin.
  (The client currently always sends the same config, so this rarely matters.)
- **Content-hash pooling.** Pins reference a global pool keyed by the SHA-256 of
  the `d` string. Two hosts on identical terrain store one copy; the reference
  count is the number of host pins. Unpinning a host decrements the count and the
  payload is evicted at zero.
- **Disconnect / mission restart.** The host's pin and its pending round-trips
  are dropped on disconnect. A reconnecting host has no pin, so its first terrain
  request is forwarded and the reply is pinned for the new mission.
- Only non-empty string payloads are cached. Errors and object replies are
  forwarded but never stored.
- Memory is capped by `MaxTotalBytes` over the **unique** payloads. A new payload
  that would exceed it is forwarded but not cached or pinned (one warning is
  logged); an already-pooled payload is always shared. There is no LRU: a payload
  lives as long as some host pins it.
- Forwarded requests that never get a reply are forgotten after
  `PendingTimeoutSeconds`.

The cache is process-local: it is not persisted, is lost on restart, and a second
relay instance would not see the first one's entries (same as every other piece
of relay state). Payloads and config contents are never logged. `TerrainCache:Enabled=false`
restores the pure forwarding behaviour, and `/health` exposes unique-payload,
byte, host-pin, hit and miss counters.

## Static compression

`wwwroot/index.html` is one large file (inline JS and CSS) and nginx **proxies**
it to this app instead of serving it from disk, so nginx's `gzip_static` /
`brotli_static` never see it. The app therefore precompresses the file itself at
startup and serves the matching variant from memory.

- **Startup:** the file is read and SHA-256 hashed. If the marker
  (`index.html.sha256`) in the cache directory matches and both variants exist
  and are non-empty, they are loaded as-is — no recompression.
- **Regeneration:** when the hash differs (you replaced `index.html`) or a
  variant is missing or empty, both variants are rebuilt with
  `CompressionLevel.SmallestSize`, kept in memory, and written to the cache
  directory together with the marker. Writes are atomic: each file goes to
  `*.tmp` and is then moved over the target, and the marker is written **last**
  so an interrupted write just triggers a regeneration on the next start.
- **Cache directory:** `TacPhone:CompressedStaticPath`; empty means
  `compressed-static` next to the SQLite database
  (`/var/lib/tacphone-remote/compressed-static` in the documented layout), which
  the systemd unit already covers through `ReadWritePaths`. Do not point it at
  `wwwroot`: `/opt` is read-only under `ProtectSystem=strict`.
- **Read-only cache:** if the directory cannot be created or written, the server
  logs one warning and keeps serving the in-memory variants. Startup is never
  blocked by this.
- **Serving:** `GET`/`HEAD` `/` and `/index.html` answer with the best variant
  the client accepts — Brotli preferred, gzip fallback, `*` treated as gzip — and
  set `Content-Type: text/html; charset=utf-8`, `Content-Encoding`,
  `Vary: Accept-Encoding`, `Content-Length` and `Cache-Control: no-store`.
  `Accept-Encoding` q-values are honoured; `q=0` disables that encoding and
  `q=0.5` still selects it.
- **Fallback:** a request that accepts neither encoding (or sends no
  `Accept-Encoding`, or arrives for an unknown path) falls through to
  `UseStaticFiles`/`MapFallbackToFile("index.html")` and gets the uncompressed
  file.
- Replacing `index.html` is detected on the next restart. There is no manual
  `gzip`/`brotli` step, and the variants are git-ignored artifacts.

The startup log records the source size, both variant sizes and whether the
variants were reused or regenerated. File contents are never logged.

## Run it locally

For a quick smoke test on a workstation (no TLS, loopback only):

```powershell
cd RemoteServer
$env:TacPhone__Port = "5080"
$env:TacPhone__DatabasePath = "data/local.db"
dotnet run --project src\TacPhone.RemoteServer
```

```bash
# Linux / macOS equivalent
cd RemoteServer
TacPhone__Port=5080 TacPhone__DatabasePath=data/local.db \
  dotnet run --project src/TacPhone.RemoteServer
```

Or put the values in `RemoteServer/.env` (or
`src/TacPhone.RemoteServer/.env`) and just run `dotnet run`:

```dotenv
TacPhone__Port=5080
TacPhone__DatabasePath=data/local.db
TacPhone__PublicBaseUrl=https://tacphone.arma3.io
```

Then `curl http://127.0.0.1:5080/health`, open `http://127.0.0.1:5080/` (the
placeholder page), and point the game or a WebSocket client at
`ws://127.0.0.1:5080/ws`. The database is created on first start; delete the
file to start from a blank slate.

## Linux setup (systemd)

All commands are for a Debian/Ubuntu-style host; adjust package names for your
distribution.

### 1. Install the runtime

```bash
# .NET 10 ASP.NET Core runtime (add dotnet-runtime-10.0 if your distro splits it)
sudo apt-get update
sudo apt-get install -y aspnetcore-runtime-10.0
# Only if the shared framework is packaged separately:
# sudo apt-get install -y dotnet-runtime-10.0

dotnet --list-runtimes   # expect Microsoft.AspNetCore.App 10.x and Microsoft.NETCore.App 10.x
```

To build on the host, install the SDK instead (`dotnet-sdk-10.0`) and skip the
publish-from-your-workstation step below. You do not need the SDK in production.

### 2. Create the service user and directories

```bash
sudo useradd --system --home /var/lib/tacphone-remote \
  --shell /usr/sbin/nologin tacphone
sudo mkdir -p /opt/tacphone-remote /var/lib/tacphone-remote/logs
```

`/opt/tacphone-remote` holds the application; `/var/lib/tacphone-remote` holds
the SQLite database and the relay log (`logs/`).

### 3. Publish

From the `RemoteServer` folder of the workspace:

```bash
cd RemoteServer
dotnet publish src/TacPhone.RemoteServer/TacPhone.RemoteServer.csproj \
  -c Release -o publish
```

### 4. Copy the files

`dotnet publish` already puts `wwwroot/` and `appsettings.json` next to the DLL,
so a single copy is enough:

```bash
sudo cp -r publish/. /opt/tacphone-remote/

sudo chown -R tacphone:tacphone /opt/tacphone-remote /var/lib/tacphone-remote
sudo chmod -R o-rwx /opt/tacphone-remote
```

If you rebuild the phone UI separately, copy its output over
`/opt/tacphone-remote/wwwroot/index.html`. `wwwroot/` and `appsettings.json`
must end up beside `TacPhone.RemoteServer.dll`, because that directory is the
content root.

### 5. Install the systemd unit

Copy the unit from [systemd unit](#systemd-unit) into
`/etc/systemd/system/tacphone-remote.service` (the same file ships as
`deploy/tacphone-remote.service` in this repository).

Optionally create the environment file the unit reads:

```bash
sudo tee /etc/tacphone-remote.env >/dev/null <<'EOF'
TacPhone__Port=5080
TacPhone__BindAddress=127.0.0.1
TacPhone__DatabasePath=/var/lib/tacphone-remote/tacphone-remote.db
TacPhone__LogFile=/var/lib/tacphone-remote/logs/tacphone-remote.log
TacPhone__PublicBaseUrl=https://tacphone.arma3.io
EOF
sudo chmod 600 /etc/tacphone-remote.env
```

### 6. Start it

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tacphone-remote
sudo systemctl status tacphone-remote
```

### 7. Check it

```bash
journalctl -u tacphone-remote -f
# The same records, without journald:
sudo tail -f /var/lib/tacphone-remote/logs/tacphone-remote.log
curl -s http://127.0.0.1:5080/health
```

`/health` answering `{"status":"ok", ...}` means the process is up, the port is
bound and the request pipeline works. If it fails, the journal is the first place
to look.

## Windows setup

### 1. Publish

From the `RemoteServer` folder, in PowerShell:

```powershell
dotnet publish src\TacPhone.RemoteServer\TacPhone.RemoteServer.csproj -c Release -o publish
New-Item -ItemType Directory -Force C:\TacPhoneRemote
Copy-Item -Recurse -Force publish\* C:\TacPhoneRemote\
Copy-Item -Recurse -Force src\TacPhone.RemoteServer\wwwroot C:\TacPhoneRemote\
```

Resulting layout:

```
C:\TacPhoneRemote\
  TacPhone.RemoteServer.dll
  appsettings.json
  wwwroot\index.html
  data\tacphone-remote.db        (created on first start)
  logs\tacphone-remote.log       (created on first start)
```

### 2. Try it in the console first

```powershell
cd C:\TacPhoneRemote
dotnet TacPhone.RemoteServer.dll
```

`dotnet` must be on `PATH`; the ASP.NET Core 10 runtime is required. Watch the
console output, then press `Ctrl+C`.

### 3. Register a service

```powershell
sc.exe create TacPhoneRemote binPath= "\"C:\Program Files\dotnet\dotnet.exe\" \"C:\TacPhoneRemote\TacPhone.RemoteServer.dll\"" start= auto
sc.exe start TacPhoneRemote
```

To remove it later:

```powershell
sc.exe stop TacPhoneRemote
sc.exe delete TacPhoneRemote
```

`binPath` quoting is fiddly (`sc.exe` wants `key= value` with a space after the
equals sign, and the whole command line escaped again for the service manager).
If it misbehaves, **NSSM** or the **Task Scheduler** ("Run whether user is logged
on or not", trigger "At startup", action `dotnet` with
`C:\TacPhoneRemote\TacPhone.RemoteServer.dll` as the argument and
`C:\TacPhoneRemote` as the working directory) are the friendlier options. The
working directory matters: it is the content root, so `wwwroot/` and the default
`data/` path resolve relative to it.

### 4. Configuration overrides

Use system-wide environment variables:

```powershell
setx /M TacPhone__Port 5080
setx /M TacPhone__BindAddress 127.0.0.1
setx /M TacPhone__DatabasePath C:\ProgramData\TacPhoneRemote\tacphone-remote.db
setx /M TacPhone__LogFile C:\ProgramData\TacPhoneRemote\logs\tacphone-remote.log
setx /M TacPhone__PublicBaseUrl "https://tacphone.arma3.io"
```

Restart the service (or reboot) for the service manager to pick them up. `setx`
only affects processes started afterwards.

### 5. Firewall

Open `80` and `443` **for nginx only**. Never open the app port (`5080`, or `443`
if you bound that directly) — the app has no TLS and no authentication beyond the
relay protocol. If nginx runs on another machine, restrict the app port to that
machine's address instead of opening it generally.

## systemd unit

The full unit, verbatim. The same file lives in
[`deploy/tacphone-remote.service`](deploy/tacphone-remote.service); install it as
`/etc/systemd/system/tacphone-remote.service`.

```ini
[Unit]
Description=TacPhone Remote Server (relay + static web UI)
Documentation=https://tacphone.arma3.io/
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=tacphone
Group=tacphone
WorkingDirectory=/opt/tacphone-remote
ExecStart=/usr/bin/dotnet /opt/tacphone-remote/TacPhone.RemoteServer.dll
Restart=always
RestartSec=5
TimeoutStopSec=20
KillSignal=SIGTERM
SyslogIdentifier=tacphone-remote

# Optional overrides: config keys can also live here as
# TacPhone__Port=5080, TacPhone__BindAddress=127.0.0.1,
# TacPhone__LogFile=/var/lib/tacphone-remote/logs/tacphone-remote.log, etc.
EnvironmentFile=-/etc/tacphone-remote.env
Environment=DOTNET_ENVIRONMENT=Production
Environment=ASPNETCORE_ENVIRONMENT=Production

# Only needed when binding 443 directly instead of using nginx.
AmbientCapabilities=CAP_NET_BIND_SERVICE

# Hardening. Do NOT add MemoryDenyWriteExecute: the .NET JIT needs W+X memory.
NoNewPrivileges=true
PrivateTmp=true
PrivateDevices=true
ProtectSystem=strict
ProtectHome=true
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
ProtectClock=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
RestrictNamespaces=true
RestrictRealtime=true
LockPersonality=true
SystemCallArchitectures=native
ReadWritePaths=/var/lib/tacphone-remote
LimitNOFILE=65535
UMask=0027

[Install]
WantedBy=multi-user.target
```

Two things that are easy to get wrong:

- `ReadWritePaths=/var/lib/tacphone-remote` is the **only** writable path
  (`ProtectSystem=strict` makes the rest read-only). `TacPhone:DatabasePath` must
  point inside it, or the service starts and then fails to open its database.
  The default `data/tacphone-remote.db` is relative to
  `WorkingDirectory=/opt/tacphone-remote`, which is read-only — so either set
  `TacPhone__DatabasePath=/var/lib/tacphone-remote/tacphone-remote.db` or add
  `/opt/tacphone-remote/data` to `ReadWritePaths`.
- `MemoryDenyWriteExecute=true` must **not** be added. The .NET JIT needs
  write-and-execute memory; the service will crash on startup if you set it.

The full example, verbatim. The same file lives in
[`deploy/nginx-tacphone.conf.example`](deploy/nginx-tacphone.conf.example).

```nginx
# Example nginx site for the TacPhone Remote Server (HTTP/3 optional).
#
# Move to /etc/nginx/sites-available/tacphone.arma3.io and symlink into
# sites-enabled. The .NET app listens on plain HTTP (default 127.0.0.1:5080).
#
# HTTP/3 requires nginx built with --with-http_v3_module (1.25.0+). It serves
# the static page and /health only: the WebSocket relay always uses HTTP/1.1
# Upgrade, because browsers do not speak WebSocket over HTTP/3.
# Check with: nginx -V 2>&1 | grep -o http_v3_module
# To disable it on a build without HTTP/3, comment out the marked HTTP/3 block
# and the Alt-Svc header below.

map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    listen [::]:80;
    server_name tacphone.arma3.io;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;

    # ---- HTTP/3 (optional) ------------------------------------------------
    # If nginx was not built with --with-http_v3_module (1.25.0+), comment out
    # this whole block and the Alt-Svc header below. The site keeps working on
    # HTTP/1.1 + HTTP/2; only the QUIC listener disappears.
    listen 443 quic reuseport;
    listen [::]:443 quic reuseport;
    http3 on;
    quic_retry on;
    ssl_early_data on;
    # ---- end HTTP/3 --------------------------------------------------------

    http2 on;

    server_name tacphone.arma3.io;

    ssl_certificate     /etc/letsencrypt/live/tacphone.arma3.io/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tacphone.arma3.io/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_session_cache   shared:SSL:10m;

    # Comment out with the HTTP/3 block above if nginx has no v3 support.
    add_header Alt-Svc 'h3=":443"; ma=86400' always;

    # Terrain SVGs and app bundles travel in a single WebSocket message.
    client_max_body_size 32m;

    location / {
        proxy_pass http://127.0.0.1:5080;
        proxy_http_version 1.1;

        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Long-lived game connections: do not cut them at the default 60 s.
        proxy_buffering         off;
        proxy_request_buffering off;
        proxy_read_timeout      1h;
        proxy_send_timeout      1h;
    }
}
```

### Installing the site

```bash
sudo cp deploy/nginx-tacphone.conf.example /etc/nginx/sites-available/tacphone
sudo ln -s /etc/nginx/sites-available/tacphone /etc/nginx/sites-enabled/tacphone
sudo nginx -t
sudo systemctl reload nginx
```

Replace `tacphone.arma3.io` with your own name everywhere (in `server_name`, the
certificate paths and `PublicBaseUrl`). For a Let's Encrypt certificate, issue it
before or after enabling the site — the example expects certbot's default
`/etc/letsencrypt/live/<name>/fullchain.pem` and `privkey.pem`:

```bash
sudo certbot certonly --nginx -d tacphone.arma3.io
sudo systemctl reload nginx
```

Notes on the proxy block:

- `proxy_set_header Upgrade` / `Connection` are **required**. Without them the
  `/ws` handshake never becomes a WebSocket and the phone UI cannot attach.
- `proxy_read_timeout 1h` and `proxy_send_timeout 1h` are **required** for the
  long-lived game socket. The nginx defaults are 60 s, which is exactly the
  "everything disconnects after a minute" symptom.
- `client_max_body_size 32m` matches `TacPhone:Limits:MaxFrameBytes`. A terrain
  SVG or a large app bundle travels in a single WebSocket message; a smaller
  limit truncates it at the HTTP layer before the app ever sees it.

### HTTP/3 (optional)

HTTP/3 serves only the static page and `/health`. **Browsers do not speak
WebSocket over HTTP/3**, so the relay stays on an HTTP/1.1 `Upgrade` connection
regardless; enabling QUIC speeds up the first page load and nothing else.

It requires nginx built with `--with-http_v3_module` (nginx 1.25.0 or newer). Check:

```bash
nginx -V 2>&1 | grep -o http_v3_module
```

If that prints nothing, comment out **both** the `---- HTTP/3 (optional) ----`
block (the two `listen … quic` lines, `http3`, `quic_retry`, `ssl_early_data`)
**and** the `add_header Alt-Svc …` line — they must be removed together, because
advertising `h3` without a QUIC listener sends browsers to a port that will never
answer. The site keeps working on HTTP/1.1 and HTTP/2.

## Backups

The only state is the SQLite database:

```
/var/lib/tacphone-remote/tacphone-remote.db
/var/lib/tacphone-remote/tacphone-remote.db-wal
/var/lib/tacphone-remote/tacphone-remote.db-shm
```

The database runs in WAL mode, so a plain `cp` of the `.db` file alone is not a
consistent snapshot. Either stop the service first:

```bash
sudo systemctl stop tacphone-remote
sudo cp /var/lib/tacphone-remote/tacphone-remote.db* /var/backups/tacphone/
sudo systemctl start tacphone-remote
```

or take an online backup:

```bash
sudo -u tacphone sqlite3 /var/lib/tacphone-remote/tacphone-remote.db \
  ".backup '/var/backups/tacphone.db'"
```

Losing this file invalidates **every** host identity, device token and share.
Affected games are issued a new identity on their next arm (their stored secret
no longer matches), and every paired browser must pair again with a one-time
code. That is recoverable, not fatal — but plan for the re-pairing.

`wwwroot/index.html` and `appsettings.json` are configuration, not state; back
them up with the rest of `/opt/tacphone-remote` if you do not keep the publish
output elsewhere.

## Upgrade

```bash
sudo systemctl stop tacphone-remote

# from the RemoteServer folder
dotnet publish src/TacPhone.RemoteServer/TacPhone.RemoteServer.csproj \
  -c Release -o publish.new
sudo cp -r publish.new/. /opt/tacphone-remote/
sudo chown -R tacphone:tacphone /opt/tacphone-remote

sudo systemctl start tacphone-remote
curl -s http://127.0.0.1:5080/health
journalctl -u tacphone-remote -f
```

Things the swap must not lose:

- the database, which lives outside `/opt` in the recommended layout
  (`/var/lib/tacphone-remote/tacphone-remote.db`) and is simply left alone,
- `appsettings.json` if you edited it in place — the publish output contains the
  shipped defaults, so re-apply your edits or keep them in
  `/etc/tacphone-remote.env`,
- `wwwroot/index.html` when you build the phone UI separately: publish copies the
  placeholder from the repository, so copy your real UI build over it again.
  The precompressed Brotli/gzip variants are regenerated automatically on the
  next start because the source hash changed (see
  [Static compression](#static-compression)); delete
  `compressed-static/` next to the database if you want to force it.

Schema migrations run automatically at startup and are additive: new tables and
columns are created, existing rows are preserved. There is no downgrade path —
going back to an older build after a forward migration is not supported, so keep
the pre-upgrade backup.

## Health check usage

```bash
curl -s https://tacphone.arma3.io/health | jq
```

```json
{
  "status": "ok",
  "version": "0.1.0",
  "uptimeSeconds": 86412,
  "hostsOnline": 3,
  "clientsOnline": 7,
  "terrainCacheEntries": 2,
  "terrainCacheBytes": 18734210,
  "terrainCacheHosts": 3,
  "terrainCacheHits": 41,
  "terrainCacheMisses": 5
}
```

| Field | Meaning |
| --- | --- |
| `status` | `"ok"` when the process is serving. Anything else is a failure. |
| `version` | Server build version, useful to confirm an upgrade actually landed. |
| `uptimeSeconds` | Seconds since process start. |
| `hostsOnline` | Game sockets currently connected. |
| `clientsOnline` | Browser sockets currently connected. |
| `terrainCacheEntries` | Unique terrain payloads currently pooled. |
| `terrainCacheBytes` | Total size of the unique pooled payloads (base64 characters). |
| `terrainCacheHosts` | Game hosts with a pinned terrain result. |
| `terrainCacheHits` | Terrain requests answered from a host's pin since start. |
| `terrainCacheMisses` | Terrain requests that had to be forwarded to the game. |

What to alert on:

- the endpoint is unreachable or returns non-200 (process down, nginx down, port
  mismatch),
- `status` is not `"ok"`,
- `version` does not change after a deploy,
- `uptimeSeconds` resets unexpectedly (crash loop — `Restart=always` masks it),
- `hostsOnline` / `clientsOnline` are implausible for your player count
  (a persistent `0` with players in game means the game cannot reach `/ws`).

The endpoint is anonymous and cheap: no database access, no allocation of
per-request state. Polling it every 30–60 s from an external monitor is fine.

## Security notes

- **Relay traffic is plaintext at the server.** TLS ends in nginx; the application
  frames between nginx and the app cross loopback in the clear. Anyone with root
  or journal access to the host can read them. Do not host the relay somewhere you
  do not trust with the phone UI's contents.
- **Secrets are never logged.** Host secrets, device tokens, pair codes and share
  keys appear only as SHA-256 hashes in the database and in constant-time
  comparisons. Log lines carry host ids, peer ids and reasons — never bearer
  values.
- **The one-time code and the share key are bearer capabilities.** Whoever has
  them gets full control of that phone: commands, interests, file reads. Do not
  paste them into public channels, and do not stream the panel while a code is on
  screen.
- **Rate limits** apply to attach attempts per client IP and per share, so brute
  forcing a 10-character code over the public internet is not practical. Repeated
  failures are logged without the attempted value.
- **Keep the app bound to loopback.** `TacPhone:BindAddress=127.0.0.1` plus nginx
  on the same host is the intended shape. There is no TLS and no request
  authentication on the static page or `/health`.
- **`TrustedProxies` must list your proxy.** If it does not, every request appears
  to come from `127.0.0.1` and the per-IP rate limit becomes a global one.
- **No `GetFile` allowlist — by decision.** Only packed, public game and mod files
  are ever served through the relay, so an allowlist would add cost without
  protection. This is recorded as a decision in
  [`../TODO.md`](../TODO.md), not as an omission.

## Troubleshooting

| Symptom | Likely cause / fix |
| --- | --- |
| nginx returns `502 Bad Gateway` | The app is not running, or `proxy_pass` points at the wrong port. Check `systemctl status tacphone-remote` and that `TacPhone__Port` matches the `proxy_pass` line (`5080` in the example). |
| WebSocket disconnects after ~60 s | Missing `proxy_read_timeout` / `proxy_send_timeout` (nginx default is 60 s), or the `Upgrade`/`Connection` headers are not proxied. Copy the `location /` block from the example verbatim. |
| `/ws` returns `400` | The request was not a WebSocket upgrade, or it arrived without the expected headers. Opening `/ws` in a browser address bar always produces this. |
| Every client is rate-limited at once | nginx's address is not in `TacPhone:TrustedProxies`, so all clients look like one IP. Add the proxy address (loopback by default) and restart. |
| `database is locked` in the journal | Two processes are using the same DB file. Only one instance may run — the in-memory registry cannot be shared. Stop the duplicate. |
| Permission denied starting on port 443 | Binding a privileged port needs `CAP_NET_BIND_SERVICE` (set in the unit) or a privileged user. Prefer nginx on 443 and the app on 5080. |
| Clients disconnect after `IdleTimeoutSeconds` | The peer sent no frame and did not answer the keepalive `{"t":"ping"}`. Reply with `{"t":"pong"}` or send any frame to keep the socket alive. |
| `dotnet` not found in the unit | Install the runtime system-wide, or change `ExecStart` to the absolute `dotnet` path. |
| Service starts then exits with a database error | `TacPhone:DatabasePath` points outside `ReadWritePaths=/var/lib/tacphone-remote`. See [systemd unit](#systemd-unit). |
| Service crashes immediately with a JIT/exec error | `MemoryDenyWriteExecute=true` was added. Remove it. |
| Cannot find the relay logs | `TacPhone:LogFile` (default `logs/tacphone-remote.log` under the content root) and `journalctl -u tacphone-remote`. Set an absolute path on production. |
| `TacPhone file logging disabled ...` on stderr | The log directory is not writable (for example the default under `/opt` with `ProtectSystem=strict`). Point `TacPhone__LogFile` at `/var/lib/tacphone-remote/logs/tacphone-remote.log`. |
| `unknown control frame` in the log | A peer sent a JSON control frame with a `t` the server does not know. The warning now includes the raw frame with credential fields redacted; the game also gets the preview in the error frame. Update the peer and server to the same protocol version. |

## Wire protocol (short version)

Control frames are WebSocket **text** messages, JSON, always with a `t` field.
Application frames are **binary**. A peer id is server-generated and identifies
the browser socket, not the person.

| Direction | `t` values |
| --- | --- |
| game → server | `auth`, `code-new`, `share-create`, `share-revoke`, `kick`, `ping`, `pong` |
| server → game | `auth-ok`, `peer-joined`, `peer-left`, `code`, `code-used`, `share`, `share-revoked`, `error`, `pong` |
| browser → server | `attach`, `ping`, `pong` |
| server → browser | `attach-ok`, `host-offline`, `rejected`, `peer-kicked`, `pong` |

Application frames:

- **Game side** uses a binary envelope:
  `0x01 | peerIdLen (u8) | peerId (ASCII) | application JSON (UTF-8)`.
  Text game frames of the form `<peerId>\n<json>` are also accepted.
- **Browser side** sends the raw application JSON as a binary message; the peer id
  is implied by the socket. The server adds the envelope when forwarding to the
  game and strips it on the way back.
- One WebSocket message is one application frame. No chunking. Frames larger than
  `MaxFrameBytes` close that peer with a protocol error.

Identifiers are opaque strings: host ids are 10 Crockford base32 characters, pair
codes are `XXXX-XXXX-XX`, share keys are 16 Crockford base32 characters, and host
secrets / device tokens are 128-bit values encoded as base64url (22 characters,
no padding). Clients must treat secrets and tokens as opaque and store them
verbatim. `auth-ok` carries `secret` only when the server had to mint a new
identity; the `share` frame carries both the raw `key` and the ready-to-open
`url`, plus `expiresIn`.

The share key is returned exactly once, when it is minted: the database only
keeps its SHA-256 hash. A game that reconnects (new process, e.g. a mission
restart) therefore cannot be reminded of the old link and must either keep the
URL in its own state or call `share-create` again — which mints a new key and
invalidates the previous link and its devices, by design.

The full spec — every field, every error code, the attach exchanges and the
compatibility handshake — is in
[`../tacphone-remote-relay.md`](../tacphone-remote-relay.md).

## TODO / not implemented

- **Device labels are read-only.** They are derived from the browser's
  `User-Agent`, truncated to 80 characters. Making them user-editable is a TODO.
- **`wwwroot/index.html` in this repository is a placeholder.** Replace it with
  the real phone UI build output after `npm run build` (copy the generated
  `index.html` and any inlined assets). The server does not build the web UI.
- **No TLS in the app.** nginx (or another terminator) does TLS.
- **No accounts.** Identities and tokens are the only credentials.
- **No message history.** Frames exist only while both peers are connected.
- **No cluster mode.** One process owns all in-memory state.
